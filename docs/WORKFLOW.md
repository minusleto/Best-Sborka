# Как менять сборку и не ломать мир

Памятка для хоста (владельца мира) и разработки. Главная идея: **данные менять можно свободно, реестр (ID) — нельзя**.

## 1. Что безопасно, а что нет

| Что меняем | Риск для мира | Как применять |
|---|---|---|
| Рецепты, теги, лут, квесты (без смены ID), `server_scripts` | Нет | `/reload` в игре, перезапуск не нужен |
| Текстуры, локализация, `client_scripts`, `assets` | Нет | `F3 + T` (перезагрузка ресурсов) |
| Конфиги модов | Обычно нет | Перезапуск игры |
| **Новые** предметы/блоки (`startup_scripts`, `bs-machines`) | Нет | Перезапуск игры, версия у хоста и гостей одинаковая |
| **Удаление или переименование** предмета/блока/машины | **Да, мир теряет их навсегда** | Не делать (см. раздел 3) |
| Смена формата NBT/данных машины | **Да, машины в мире не читаются** | Только с обратной совместимостью |
| Обновление или удаление мода | **Да** | Только в тестовом мире и с бэкапом |
| Смена ID квестов/глав/наград | Потеря прогресса квестов | Не менять у существующих квестов |

## 2. Рабочий цикл

1. **Бэкап мира перед каждым обновлением.** Windows: двойной клик по `scripts\backup-world.bat` (или `backup-world.bat "Имя мира"`), Linux/macOS: `scripts/backup-world.sh`. Архивы лежат в `backups/` (в Git не попадают), хранятся последние 10 на мир. Игру можно не закрывать, но лучше выйти в главное меню: файл `session.lock` пропускается, а уже записанные данные копируются как есть.
   Встроенный способ без скриптов: Одиночная игра → выбрать мир → «Изменить» → «Создать резервную копию».
2. **Проверить изменение в копии мира.** Сделайте копию (`saves/Мир` → `saves/Мир-тест`) или создайте плоский творческий мир и проверьте там: рецепты в JEI, машины, предметы, `logs/latest.log` без ошибок KubeJS.
3. **Запустить проверку:** `python scripts/validate.py`. Она читает все JSON (включая дубли ключей в локализации), проверяет синтаксис `.js` и следит, чтобы ID предметов/блоков не пропали. То же самое запускается в GitHub Actions после каждого пуша.
4. **Записать в `CHANGELOG.md`** раздел `[Unreleased]`: что добавлено, изменено, исправлено; отметить ⚠, если нужно обновить всех или есть риск для миров.
5. **Выпуск версии для друга:** перенести `[Unreleased]` в раздел `## [0.X.Y] - дата`, затем
   `git tag v0.X.Y && git push origin v0.X.Y`. Actions соберёт релиз: `Best-Sborka-v0.X.Y-overrides.zip` (папки `config` и `kubejs`) и `bs-machines-*.jar`.
6. **Играть на выпущенной версии.** Чиним баги в `main` сколько угодно, но мир хоста и друга обновляем только на готовый тег. Так «рабочая версия» всегда известна.

## 3. Правила для ID (почему ломается мир)

Мир хранит ссылки на предметы и блоки по ID (`kubejs:iron_plate`, `bs_machines:assembler`). Если ID исчез, Forge предлагает «продолжить без недостающих», и всё, что было в сундуках, на земле и в машинах, **удаляется навсегда**.

- Не удаляем и не переименовываем зарегистрированные ID. Если предмет больше не нужен: убираем его рецепты, прячем из JEI, при желании делаем рецепт обмена на новый. Сам ID остаётся зарегистрированным.
- Это проверяет `scripts/validate.py` по файлу `scripts/registry.lock`. После **добавления** новых ID запускайте `python scripts/validate.py --update-lock` и коммитьте обновлённый lock. Удаление ID из lock вручную означает осознанное решение «мы ломаем миры»; делаем только в новой версии с пометкой ⚠ Ломающее и бэкапом.
- Машины `bs-machines`: при чтении NBT недостающие поля должны получать значения по умолчанию, чтобы старые машины в мире оставались рабочими. Поля не переименовываем.
- Квесты: ID квестов, задач и наград у существующих квестов не меняем (формат ID описан в [quests.md](quests.md)).

## 4. Хост и друг: что обновлять

Мир лежит у хоста; у друга его копии нет. Но при входе Forge сверяет моды и реестр: если версии различаются, вход невозможен.

- Изменения **только** в `server_scripts` (рецепты, теги, лут): обычно достаточно обновить хоста, рецепты и теги синхронизируются с гостем при входе.
- Изменения в `startup_scripts`, `assets`, `client_scripts`, конфигах, jar-файлах: **обновлять нужно обоих**, одинаковой версией.
- Установка версии (у каждого игрока): закрыть игру → бэкап мира (хост) → удалить папку `kubejs` в папке сборки → распаковать `Best-Sborka-vX-overrides.zip` с заменой → заменить `bs-machines-*.jar` в `mods` (старый удалить) → запустить.
- Сторонние моды в Git не хранятся. Если версия мода меняется, указывайте это в `CHANGELOG.md` и передавайте друг другу файл напрямую, список лежит в [mods-list.md](mods-list.md).

## 5. Если мир сломался

1. **Ничего не сохранять поверх.** Закройте игру, скопируйте папку мира целиком в безопасное место.
2. Посмотрите `logs/latest.log` и `crash-reports/` (последний файл). Ищите строки `ERROR`, `Missing registry`, `Failed to load`, `KubeJS`.
3. Типовые случаи:
   - «Missing registry entries / предметы будут удалены»: **не подтверждайте**. Нажмите «Отмена», верните удалённый ID (откат коммита) и зайдите снова.
   - Ошибка в скрипте KubeJS: исправьте или откатите файл и выполните `/reload`. Мир при этом не повреждается, просто не загрузятся рецепты.
   - Вылет при загрузке чанка с машиной: откат версии `bs-machines` и NBT-формата.
4. Откат: восстановить мир из `backups/` (распаковать архив в `saves/`) и откатить сборку на предыдущий тег.
5. После исправления выпустить новый патч `v0.X.Y+1` и записать причину в `CHANGELOG.md`.

## 6. Чек-лист перед выпуском версии

- [ ] Бэкап мира сделан.
- [ ] Изменения проверены в копии мира (JEI, машины, `latest.log` без ошибок).
- [ ] `python scripts/validate.py` проходит.
- [ ] Новые ID добавлены в `scripts/registry.lock` (`--update-lock`).
- [ ] Заполнен `CHANGELOG.md`, отмечены ⚠.
- [ ] Тег поставлен, релиз собрался в разделе Releases на GitHub, друг установил именно его.

См. также [claude-review-checklist.md](claude-review-checklist.md) для проверки рецептов.
